# PULSE Telegram Mini App and Bot Deployment Guide

This guide configures the PULSE Telegram Mini App through BotFather's graphical interface. Typing BotFather setup commands is not required. The bot is a navigation, report-delivery and Autopilot-reminder channel; it never holds a wallet key. Wallet connections, x402 payments and transaction signatures remain inside the PULSE web application.

Official references:

- [Telegram Mini Apps](https://core.telegram.org/bots/webapps)
- [Telegram Bot API: `setWebhook`](https://core.telegram.org/bots/api#setwebhook)
- [Telegram Bot API: `getWebhookInfo`](https://core.telegram.org/bots/api#getwebhookinfo)

## 1. Understand the URLs and secrets

The four Telegram environment values do not come from the same place.

| Variable | Where it comes from | PULSE production value or rule |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | BotFather's bot-management screen | Copy the API token once and keep it server-only. |
| `TELEGRAM_BOT_USERNAME` | The username displayed under the bot name | `pulsemi_bot` for the current bot; omit `@`. |
| `TELEGRAM_MINI_APP_URL` | The deployed PULSE **web frontend** | `https://www.ai-pulse.tech` |
| `TELEGRAM_WEBHOOK_SECRET` | Generated by the operator, not by Telegram | A new random 32-byte value encoded as 64 hexadecimal characters. |

There is also a webhook URL:

```text
https://<PUBLIC-RAILWAY-API-HOST>/v1/telegram/webhook
```

The two URLs have different purposes:

- `TELEGRAM_MINI_APP_URL` opens the PULSE user interface. For production, use the canonical non-redirecting origin `https://www.ai-pulse.tech` in both BotFather and the API environment.
- The webhook URL receives Telegram updates on the PULSE API. It uses the public Railway API origin unless a production API subdomain already points to Railway.

Do not use a `t.me` link, the Railway API URL, or `/v1/telegram/webhook` as `TELEGRAM_MINI_APP_URL`. The apex `https://ai-pulse.tech` currently redirects to the different `https://www.ai-pulse.tech` origin; do not register the redirecting apex in BotFather because Telegram binds Mini App functionality to the registered origin.

## 2. Prerequisites

- The web frontend is publicly reachable over HTTPS at `https://www.ai-pulse.tech`.
- The Railway API is publicly reachable over HTTPS and exposes `POST /v1/telegram/webhook`.
- The production API has durable KV configured for report delivery and reminders.
- Global and Prediction report jobs work before Telegram delivery is enabled.
- The Telegram account configuring the bot owns `@pulsemi_bot`.

Do not use localhost as a production Mini App or webhook URL. A temporary HTTPS tunnel is acceptable only for local testing and must be removed afterward.

## 3. Configure the bot through BotFather's interface

From the bot-management screen shown for **PULSE Market Intelligence**:

1. Open **Edit Info**.
2. Set the public name, description, about text and approved PULSE avatar.
3. Use a security statement such as: “Wallet signing happens only inside the PULSE Mini App. Never share a seed phrase or private key.”
4. Keep the displayed username `@pulsemi_bot`. The environment value is `pulsemi_bot` without `@`.
5. Copy the API token once and store it as `TELEGRAM_BOT_TOKEN` only on the API/worker host.
6. Open **Mini Apps**.
7. Create or enable the bot's **Main Mini App**.
8. Set the Web App URL to exactly `https://www.ai-pulse.tech`.
9. Set the Mini App title and description, then upload production screenshots or videos after the interface is final.
10. If BotFather offers a menu or launch button, configure it to open the same `https://www.ai-pulse.tech` URL.

Telegram's Main Mini App configuration creates the profile launch button. BotFather's **Commands** screen is not required for this workflow.

PULSE adds `source=telegram`, the selected service and a signed chat-bound delivery capability to links sent by the bot. Do not add those query parameters to the URL entered in BotFather.

## 4. Optional bot commands

Skip this section if users will open PULSE through the Main Mini App/profile button and the web-app buttons sent by the bot.

If command shortcuts are desired later, open **Commands** in BotFather's graphical interface and add:

```text
start - Open PULSE services
global - Buy a Global Market report
prediction - Buy a Prediction Market report
reports - Open report delivery history
wallet - Link, inspect, or unlink a wallet
help - Security and usage guide
```

No user needs to type these commands. Pressing Telegram's normal **Start** button may produce a `/start` update internally; PULSE handles it automatically and returns the service keyboard.

## 5. Generate `TELEGRAM_WEBHOOK_SECRET`

This value is not available in BotFather. It is an application-generated shared secret and must not equal the bot token.

Generate it once on a trusted Windows machine using a cryptographically secure random-number generator:

```powershell
$bytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
try {
  $rng.GetBytes($bytes)
  $webhookSecret = [BitConverter]::ToString($bytes).Replace('-', '').ToLowerInvariant()
} finally {
  $rng.Dispose()
}
$webhookSecret
```

The result is a 64-character hexadecimal value. Telegram permits 1–256 characters from `A-Z`, `a-z`, `0-9`, `_` and `-`, so this format is valid.

Use the identical value in exactly two places:

1. `TELEGRAM_WEBHOOK_SECRET` on the PULSE API/worker host;
2. `secret_token` in the `setWebhook` request sent to Telegram.

PULSE compares Telegram's `X-Telegram-Bot-Api-Secret-Token` request header with the environment value. A missing or different value receives HTTP 401.

## 6. Configure the environments

### Local root `.env`

The local root `.env` contains the server-side development values and is Git-ignored. Never copy it into source control.

### Railway API/worker variables

Set all of these on the Railway service that runs the PULSE API and Telegram delivery worker:

```dotenv
FEATURE_TELEGRAM=1
TELEGRAM_BOT_TOKEN=<TOKEN_FROM_BOTFATHER>
TELEGRAM_BOT_USERNAME=pulsemi_bot
TELEGRAM_WEBHOOK_SECRET=<THE_GENERATED_64_CHARACTER_SECRET>
TELEGRAM_MINI_APP_URL=https://www.ai-pulse.tech
BASE_URL=https://<PUBLIC-RAILWAY-API-HOST>
```

`BASE_URL` is the public API origin. It is not the Mini App URL unless the web and API genuinely share one origin through a configured reverse proxy.

### Vercel frontend variables

Do not put either server secret in Vercel browser variables or any `VITE_*` variable:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_WEBHOOK_SECRET`

`TELEGRAM_MINI_APP_URL` is public, but the current server implementation reads it on the API/worker, so it belongs on Railway. The Vercel site only needs to be reachable at the same non-redirecting `https://www.ai-pulse.tech` URL registered with BotFather.

After setting Railway variables, restart or redeploy the API through the normal operator-controlled process.

## 7. Verify PULSE configuration

Check the API status endpoint:

```powershell
Invoke-RestMethod https://<PUBLIC-RAILWAY-API-HOST>/v1/telegram/status
```

Expected fields:

```json
{
  "enabled": true,
  "configured": true,
  "botUsername": "pulsemi_bot",
  "botUrl": "https://t.me/pulsemi_bot",
  "webhookPath": "/v1/telegram/webhook",
  "miniAppUrl": "https://www.ai-pulse.tech",
  "custody": false,
  "durableDelivery": true
}
```

The status response also returns `missing` and `miniAppUrlError` without exposing either secret. If `configured` is false, use those fields to identify the exact Railway runtime problem. If `durableDelivery` is false, verify the KV variables on Railway before accepting paid report delivery.

## 8. Register the Telegram webhook

BotFather's **Mini Apps** screen configures the frontend launch URL; it does not register the backend webhook. Register the webhook once after the Railway API is running with the variables above.

Run this from a trusted PowerShell terminal. The prompts keep the actual values out of the saved command text:

```powershell
$botToken = Read-Host 'Paste TELEGRAM_BOT_TOKEN'
$secret = Read-Host 'Paste TELEGRAM_WEBHOOK_SECRET'
$webhookUrl = 'https://<PUBLIC-RAILWAY-API-HOST>/v1/telegram/webhook'
$body = @{
  url = $webhookUrl
  secret_token = $secret
  allowed_updates = @('message', 'callback_query')
  drop_pending_updates = $true
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri "https://api.telegram.org/bot$botToken/setWebhook" `
  -ContentType 'application/json' `
  -Body $body
```

This is an explicit external change: only run it when ready to connect Telegram to the deployed Railway API.

Check the result:

```powershell
Invoke-RestMethod "https://api.telegram.org/bot$botToken/getWebhookInfo"
```

Verify:

- `url` is the exact Railway webhook URL;
- `pending_update_count` returns to zero after a test;
- `last_error_message` is absent;
- `allowed_updates` includes `message` and `callback_query`.

Do not paste the webhook secret into BotFather, the Mini App URL, the bot description, command list, Vercel frontend variables, screenshots or source control.

## 9. Test the Mini App without command setup

1. Open `@pulsemi_bot` from a normal Telegram user account.
2. Press the profile's **Launch App/Open App** button.
3. Confirm that PULSE opens at `https://www.ai-pulse.tech` inside Telegram without changing origin.
4. Close the Mini App, press Telegram's normal **Start** button, and confirm that the bot returns PULSE service buttons.
5. Open Global Market from a bot web-app button.
6. Connect a test wallet and complete one expected x402 report purchase.
7. Confirm only one payment occurs and the durable result is delivered back to the same Telegram chat.
8. Reopen the Mini App and confirm the report remains recoverable.
9. Test a Telegram-linked Autopilot pass and confirm its reminder capability is bound to the same chat.

The delivery capability is HMAC-signed, chat-bound and valid for 35 days so it can cover the longest 30-day Autopilot pass plus its warning window. It cannot authorize a payment, wallet action, trade or report purchase.

## 10. Security and operations

- Never expose `TELEGRAM_BOT_TOKEN` or `TELEGRAM_WEBHOOK_SECRET` to browser JavaScript.
- Rotate a leaked bot token in BotFather, update Railway, and then register the webhook again.
- Generate a new webhook secret when rotating; update Railway before calling `setWebhook` with the new value.
- Do not log full Telegram payloads, wallet signatures, x402 authorizations or report access tokens.
- Full report links must remain opaque, revocable and bounded by report retention. Never send a private Blob URL to Telegram.
- Telegram update IDs are replay-protected. Retried updates must not repeat payment or analysis.
- Delivery retries start after 30 seconds and back off to a maximum one-hour interval.
- Monitor the `pulse:v6:telegram:due` KV sorted set for growing age or repeated delivery errors.

During a Telegram outage, paid jobs continue independently and delivery retries after connectivity returns.

## 11. Disable or remove the integration

Set `FEATURE_TELEGRAM=0` on the API and remove the webhook when the integration should stop:

```powershell
$botToken = Read-Host 'Paste TELEGRAM_BOT_TOKEN'
Invoke-RestMethod `
  -Method Post `
  -Uri "https://api.telegram.org/bot$botToken/deleteWebhook" `
  -ContentType 'application/json' `
  -Body '{"drop_pending_updates":true}'
```

Removing Telegram must not delete purchased reports, payment evidence or owner-controlled Autopilot state. Revoke the bot token in BotFather only if the bot will not return or the token is compromised.
