# PULSE BotFather configuration — one bot

Prepared October 4, 2026. This is the configuration to perform when you deploy. No BotFather changes, deployment, purchase or publication has been performed by preparing this guide.

**There is one product bot: PULSE, `@pulsemi_bot`.** It handles all five research services in chat, retains the Telegram account's EVM history association, and launches the TON Mini App. Both interfaces use the existing token and `/v1/telegram/webhook`. The TON API prefix identifies an interface, not another bot or another Telegram account.

Start with this guide for Telegram configuration, then use the [deployment checklist](PULSE_TELEGRAM_DEPLOYMENT.md).

## 2. Open the correct BotFather and bot

1. Open [@BotFather](https://t.me/BotFather) using the Telegram account that owns PULSE. Confirm the username is exactly `BotFather`.
2. Press **Start** if necessary.
3. Send `/mybots`.
4. Select the existing bot with username **@pulsemi_bot**. Check the username even if the current display name is different.
5. Keep that bot selected for each setting below. If BotFather returns to its main screen, send the relevant command and select **@pulsemi_bot** again.

Use the existing bot token. If you need to retrieve it, select **API Token** on this bot's management screen or use `/token` and select **@pulsemi_bot**. Put it in the API host's secret field. Routine deployment does not require revoking it. The [official BotFather reference](https://core.telegram.org/bots/features#botfather) describes account management.

**Checkpoint:** every configuration prompt identifies @pulsemi_bot. Its display name can change; the username and existing customers remain the same.

## 3. Set the bot name

1. Send `/setname` to BotFather.
2. Select **@pulsemi_bot**.
3. Send this single line:

```text
PULSE
```

4. Wait for BotFather's success confirmation.
5. Open the PULSE bot profile and verify its visible name is **PULSE**.

The equivalent button route is `/mybots` → **@pulsemi_bot** → **Edit Bot** → **Edit Name**, when that button is available. The setup script also applies the same name, so it will not replace it with a separate TON brand.

## 4. Set “What can this bot do?”

This is the long description shown before someone starts the bot. It is different from the welcome message generated by PULSE after `/start`.

1. Send `/setdescription`.
2. Select **@pulsemi_bot**.
3. For the completed release, paste this block as one message, without the code-fence markers:

```text
PULSE brings market intelligence to Telegram. In chat: Global Quick and Prediction Quick (10 Stars); Risk Guard, Global Pro and Prediction Pro (15 Stars). Open the TON Mini App for TON-USDT research and optional TON Connect. Receive reports here and revisit My reports. Link your EVM wallet once for retained website history. Explore the full product: https://www.ai-pulse.tech.
```

4. Wait for confirmation. Reopen the bot profile/intro and inspect the saved text.

During setup with sales paused, use the same text with this sentence appended:

```text
Setup in progress: new Stars purchases are paused.
```

The prepared script appends that sentence automatically for `--stage paused` and removes it for `--stage checkout`. Both descriptions fit Telegram's 512-character limit. Do not use the completed-release copy as evidence that purchases already work.

The script uses these exact texts. Each fits the 120-character short-description limit. Telegram distinguishes this public profile text from the longer intro description. [Description fields and limits](https://core.telegram.org/bots/api#setmyshortdescription).

## 6. Set the profile photo

1. Send `/setcommands`.
2. Select **@pulsemi_bot**.
3. If a language/scope selection is offered, use the default command set. This release's command labels are English; no translated command set is supplied.
4. Paste the following entire block as one message. Command names in this BotFather block have no leading slash:

```text

```

5. Wait for confirmation.
6. Open the private PULSE chat and type `/`. Verify the commands are suggested.
7. Test `/help`, `/miniapp` and `/website` after the updated API is deployed.

The automated setup registers this list for **all private chats**. A later manual edit to a different command scope may not replace that list; rerun the setup script for the selected stage when you need to restore the release configuration. If an old language-specific list persists, inspect that specific list in BotFather rather than deleting the bot.

Commands are registered labels; actual behavior is implemented in the API. Sending `/setcommands` alone cannot enable Stars checkout or wallet history. [Command setup tutorial](https://core.telegram.org/bots/tutorial#executing-commands).

## 8. Private-chat and optional settings

BotFather menu labels can vary by Telegram client. The slash commands above select the intended setting directly; follow the current confirmation prompt rather than sending an unrelated command. [Bot management settings](https://core.telegram.org/bots/features#bot-settings).

## 9. Deploy before enabling the Mini App

Complete the API/frontend deployment instructions in [PULSE_TELEGRAM_DEPLOYMENT.md](PULSE_TELEGRAM_DEPLOYMENT.md) first, with `TELEGRAM_STARS_ENABLED=0`.

The frontend must serve these actual assets:

- `https://www.ai-pulse.tech/ton-miniapp` — the TON interface, not the generic application landing.
- `https://www.ai-pulse.tech/tonconnect-manifest.json` — JSON with name `PULSE`, the TON app URL and public icon URL.
- `https://www.ai-pulse.tech/tonconnect-icon.png` — the PNG icon used by the manifest.
- `https://www.ai-pulse.tech/og-image-v8.png` — the updated PNG link-preview image.

An HTTP 200 response is insufficient for the manifest or image: a hosting rewrite can return HTML for a missing file. The readiness checker rejects an HTML manifest fallback. The icon uses the existing PULSE PNG logo; SVG is not supported by TON Connect. [TON manifest requirements](https://docs.ton.org/applications/ton-connect/get-started#prepare-the-manifest). Open the actual Mini App from Telegram before calling its authentication/purchases verified.

## 10. Enable the Main Mini App on the same PULSE bot

1. In BotFather, send `/mybots`.
2. Select **@pulsemi_bot**.
3. Select **Bot Settings**.
4. Select **Configure Mini App**.
5. Choose **Enable Mini App** when it is not enabled. If it is already enabled, select the action that edits its current URL.
6. When asked for the Mini App URL, paste exactly:

```text
https://www.ai-pulse.tech/ton-miniapp
```

7. Complete the confirmation shown by BotFather. The app title, if requested, is **PULSE**.
8. Open the PULSE bot profile. Confirm the app launch button opens the TON research interface.
9. Test this direct link:

```text
https://t.me/pulsemi_bot?startapp
```

10. Confirm the Mini App header identifies a Telegram account rather than **BROWSER PREVIEW**.
11. Before the first checkout from a direct launch, allow PULSE to send messages when Telegram prompts. If you decline, checkout stops before invoice creation; you can reopen from the PULSE chat and press Start. This gives the bot permission to deliver the complete report.

The Main Mini App setting belongs to **@pulsemi_bot**. The URL contains `/ton-miniapp`; the token remains the original PULSE token. Telegram documents the configuration route and the `?startapp` launch format in its [Mini App guide](https://core.telegram.org/bots/webapps#launching-the-main-mini-app).

## 14. Apply the prepared configuration after deployment

From the repository root, use an operator environment containing production settings. A local development `.env` is not proof of the cloud configuration.

```powershell
node --env-file=.env.cloud scripts/telegram-setup.mjs --stage paused
node --env-file=.env.cloud scripts/telegram-setup.mjs --stage paused --apply
node --env-file=.env.cloud scripts/telegram-setup.mjs --status
```

The first command previews the exact name, descriptions, commands and URLs. The second verifies both deployed interfaces, their shared identity/webhook, paused catalogs and the JSON manifest before changing the one bot. The third reads identity, Main Mini App status, menu and webhook. `.env.cloud` is an ignored local operator file; create it with your actual production values and keep it private.

The script sets name, commands, long/short descriptions, menu and webhook. **It does not configure Main Mini App, avatar, group joining, privacy, inline mode or splash/media**; complete the manual steps above. Sequential Bot API calls are not transactional: if a later step fails, earlier ones may have applied. Inspect status and rerun only after the reported problem is fixed.

After the staffed purchase acceptance window is ready, enable Stars on the API host, verify both live catalogs, then run:

```powershell
node --env-file=.env.cloud scripts/telegram-setup.mjs --stage checkout
node --env-file=.env.cloud scripts/telegram-setup.mjs --stage checkout --apply
```

This restores the completed-release descriptions. Enabling Stars on the host and applying public bot copy are distinct operations. Do not launch acquisition until real acceptance is complete.

## 16. Platform eligibility and release status

The requested implementation is one PULSE bot with both interfaces. Technical separation of chat and TON UI does not establish Telegram approval. Telegram's blockchain guidelines also cover a Mini App's connected bot; EVM ownership links and the main website's non-TON functionality remain an eligibility-review item for the combined launch. Research text, persistent report identity, wallet interaction and promotional links are distinct considerations. [Blockchain guidelines](https://core.telegram.org/bots/blockchain-guidelines).

The release can be built and prepared with this configuration. Public readiness still requires deployment, real Stars/refund/document-delivery acceptance, real wallet/client persistence checks, a staffed contact and resolution of that platform review. The read-only checker always leaves `launchApproved=false`; it cannot replace these operational decisions.
