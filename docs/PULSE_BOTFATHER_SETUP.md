## 14. Apply the prepared configuration after deployment

From the repository root, use an operator environment containing production settings. A local development `.env` is not proof of the cloud configuration.

```powershell
node --env-file=.env.cloud scripts/telegram-setup.mjs --stage paused
node --env-file=.env.cloud scripts/telegram-setup.mjs --stage paused --apply
node --env-file=.env.cloud scripts/telegram-setup.mjs --status
```

The first command previews the exact name, descriptions, commands and URLs. The second verifies both deployed interfaces, their shared identity/webhook, paused catalogs and the JSON manifest before changing the one bot. The third reads identity, Main Mini App status, menu and webhook. `.env.cloud` is an ignored local operator file; create it with your actual production values and keep it private.

The script sets name, commands, long/short descriptions, menu and webhook. **It does not configure Main Mini App, avatar, group joining, privacy, inline mode or splash/media**; complete the manual steps above. Sequential Bot API calls are not transactional: if a later step fails, earlier ones may have applied. Inspect status and rerun only after the reported problem is fixed.

After the staffed purchase acceptance window is ready, enable Stars on the API host, verify both live catalogs, then run:

```powershell
node --env-file=.env.cloud scripts/telegram-setup.mjs --stage checkout
node --env-file=.env.cloud scripts/telegram-setup.mjs --stage checkout --apply
```

This restores the completed-release descriptions. Enabling Stars on the host and applying public bot copy are distinct operations. Do not launch acquisition until real acceptance is complete.

## 16. Platform eligibility and release status

The requested implementation is one PULSE bot with both interfaces. Technical separation of chat and TON UI does not establish Telegram approval. Telegram's blockchain guidelines also cover a Mini App's connected bot; EVM ownership links and the main website's non-TON functionality remain an eligibility-review item for the combined launch. Research text, persistent report identity, wallet interaction and promotional links are distinct considerations. [Blockchain guidelines](https://core.telegram.org/bots/blockchain-guidelines).

The release can be built and prepared with this configuration. Public readiness still requires deployment, real Stars/refund/document-delivery acceptance, real wallet/client persistence checks, a staffed contact and resolution of that platform review. The read-only checker always leaves `launchApproved=false`; it cannot replace these operational decisions.
