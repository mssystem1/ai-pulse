# PULSE Acceptance Report

Updated: 2026-08-27

This report maps the twelve requested acceptance items to the implemented product and its current verification evidence. It does not treat an unsupported token representation as a successful route and it does not repeat completed mainnet trades merely to produce new hashes.

## Twelve-point acceptance

1. **Selected-RPC DeFi mapping — complete.** The analysis ticker is resolved to the exact execution representation first (`BTC -> cbBTC`, `DOGE -> cbDOGE`, `ETH -> WETH`, where available). DeFi candidates are then accepted only when OKX product detail contains that exact chain/token contract. Results disclose APY, TVL, invest/redeem/claim capability, score and risk flags. Missing identity-safe products remain unavailable.
2. **Account discovery and RPC throttling — complete.** Spot opens with one coalesced factory snapshot for Market protection, Limit, Bracket and Autopilot accounts. Reads use factory contracts and multicall, not Etherscan. The snapshot has positive/stale caches, RPC fallback and a recoverable retry state. HAR review found the reported failures were public Base RPC HTTP 429 responses dominated by `eth_call`.
3. **Trigger, mark and P&L — complete for newly recorded positions.** Limit/Bracket trigger comes from contract state, mark comes from live OKX price, and estimated P&L uses the recorded position basis. A protected Market buy records the confirmed fill transaction and derives exact settlement spent/asset received from ERC-20 transfer logs. Legacy positions without provable basis say “Fill basis unavailable” rather than displaying a fabricated zero.
4. **Stable order lifecycle — complete.** Terminal and protected states cannot regress during a transient read. OTOCO is Pending before entry fill, Active while its received asset is under TP/SL, then Executed or Cancelled once terminal. Each transaction is stored in its own atomic KV hash field and cross-worker reconciliation keeps the newest update, eliminating shared-list overwrite and Pending/Active flapping. A protected Autopilot Buy counts as Active and is not also counted as Executed; strategy P&L is included in the shared dashboard estimate.
5. **Dashboard filters — complete.** Both trading dashboards expose All, Pending, Active, Executed, Cancelled and Activity. Activity remains the transaction ledger; order-state counts are not inferred from unrelated account-creation receipts.
6. **Autopilot fifth-step failure — fixed and recovered live.** Existing vaults are discovered before creation. Policy updates safely pause an already-running vault, remove an obsolete allowed target when the asset changes, configure the new policy, and only report a paused recovery state when a pause actually succeeded. The API worker uses a distributed KV execution lease plus the contract nonce guard. The X Layer run also exposed a false cold-start KV timeout and a stale shared-snapshot race. The bounded deadline is now 6 seconds and strategies use atomic per-vault KV hash fields with runtime-only merges. The same active strategy recovered without recreating its vault or moving capital, and the ordinary scheduler produced a new evidence-backed Hold after recovery.
7. **Autopilot capital — complete.** Capital is the selected vault's exact settlement-token balance: USDC on Base/Arbitrum or USDT0 on X Layer. Existing funded capital is displayed and reused; PULSE does not request a duplicate deposit. Add, withdraw, pause and resume remain owner wallet actions.
8. **Shared dashboard — complete.** Spot and Autopilot render the same reconciled `ActivityDashboard` component with the same state definitions and filters, scoped independently by source.
9. **Report-to-order flow — superseded by the current split workflow.** A Buy report offers wallet-signed Market or Limit Spot execution. Pair, timeframe, entry, TP and SL travel together. Autopilot now starts independently with its own deterministic gate and compact prepaid AI confirmation; it does not inherit or repeatedly purchase a Global report.
10. **Product guidance — complete.** A persistent journey explains Analyze -> Spot or Autopilot; the product-wide Opportunity Radar appears in Global, empty Spot and Autopilot as a research shortlist. Global uses an RPC-themed accessible timeframe picker. Report actions visibly lead to prefilled Agentic-Wallet-signed Market or Limit flows, while Autopilot starts separately from its own fresh signal policy. The execution UI hides contract addresses and atomic units under technical proof, checks route and wallet balance separately, explains disabled actions, suggests a verified alternative network, and links to OKX Spot when no supported onchain representation exists. Risk Guard is promoted before execution features and browses token contracts on all four networks. Docs contain navigation, charts, diagrams, complete Spot/Autopilot examples and troubleshooting.
11. **Buy-only analysis — complete.** Global analysis creates only Buy or Wait recommendations. Sell remains available only as an explicit owner action to exit an asset already held; it is not emitted as an analysis recommendation.
12. **Mainnet workflow matrix — complete.** Manual Spot routes, multi-agent strategy coverage, genuine autonomous Buy, protected Hold, natural take-profit, bounded partial/final Sell, realized P&L reconciliation and a later policy-qualified re-entry are all confirmed. The X Layer SOL-USDT 1D strategy closed its first position for `+6,458` USDT0 atomic (`+0.6458%`) and then opened a new `0.1 USDT0` position only after a fresh 72% compact AI confirmation passed all five Trend Following entry rules. Additional live agents cover X Layer ETH 15m Mean Reversion, Base DOGE 15m Breakout and Arbitrum BTC 1H Mean Reversion with `0.5` settlement token each. PULSE never forced a trade while its signed conditions were absent.

## Operator-owned external setup

The Telegram implementation is wired and enabled, but the local environment intentionally reports `configured: false` until the operator supplies a BotFather token, username, webhook secret and public HTTPS Mini App URL. Follow `docs/TELEGRAM_BOT_DEPLOYMENT.md`; no software change is required. PULSE never generates or owns those Telegram credentials.

Public-source verification and deterministic contract tests are present, but they are not a substitute for an independent smart-contract security audit. Use bounded capital until that external review is complete.
